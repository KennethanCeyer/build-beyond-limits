# 단계별 구현 직후 검증 절차

클라이언트 기능을 단계별로 작성할 때는 이전 단계의 버그가 누적되지 않도록 각 단계가 끝날 때마다 아래 확인을 먼저 마친 뒤 다음 단계로 넘어갑니다.

## 공통 확인 (매 단계 종료 시)

1. 작성한 스크립트와 모듈의 문법 검사(`node --check`) 또는 번들 빌드(`npm run build`)가 오류 없이 끝나는지 확인합니다.
2. 로컬 웹 서버로 클라이언트를 실행해 브라우저 콘솔 예외와 리소스 `404` 응답이 `0건`인지 확인합니다.

## Step 1 완료 후: 접속, 토큰 연동, 직업 선택, 맵과 이동 및 공격

1. `diagnose_server_health` 도구로 라이브 서버(`http://34.158.215.133:8080`) 상태를 확인합니다.
2. URL 쿼리 `?token=<TOKEN>`으로 접속했을 때 `POST /api/auth/verify` 검증을 거쳐 `localStorage['bbl_player_identity_v1']`에 저장되고 새로고침 후에도 같은 `codename`이 유지되는지 확인합니다.
3. 작성한 이동 및 공격 페이로드를 `validate_client_payload` 도구로 검증합니다.
4. `map_init`의 `72x52` 타일 데이터로 던전이 화면에 그려지고, 직업 선택 후 이동과 공격을 보냈을 때 `inspect_player_state`에서 내 캐릭터의 좌표와 `ackSeq`가 실제로 갱신되는지 확인합니다.

## Step 2 완료 후: `BBL-BIN v1` 바이너리 디코더, 연출, 오디오, 막기, 패링, 강공격

1. 라이브 서버에서 수신한 `0x81 S2C_STATE` 바이너리 `ArrayBuffer`를 디코딩했을 때 마지막 읽기 오프셋이 `byteLength`와 정확히 일치하는지 검증 스크립트나 단위 테스트로 확인합니다.
2. 공격 대기시간 종료 후 `charge_start` -> `attack` 순서로 강공격(`heavy: true`)이 나가는지, `guard` 유지 막기와 피격 직전 패링 판정, 대시 이동이 동작하는지 확인합니다.
3. 첫 입력 이후 Web Audio `AudioContext`가 활성화되어 전투 효과음과 구역별 배경음악이 오류 없이 재생되는지 확인합니다.

## Step 3 완료 후: 미니맵, 10칸 가방과 장비 비교, 스킬 트리, 능력치 배분

1. `20Hz state` 패킷이 계속 수신되는 상태에서 `[I]` 또는 `[Tab]` 창을 열고 장비 장착, 아이템 버리기, `[Q]`/`[R]` 스킬 습득 및 강화, 능력치(`str`, `vit`, `agi`) 투자 버튼을 눌렀을 때 클릭 유실 없이 반영되는지 확인합니다.
2. `1280x800`과 프리뷰 크기인 `800x500` 해상도에서 좌측 상단 영웅 상태창(치명타 확률 등), 미니맵, 하단 슬롯, 장비 비교 툴팁이 화면 밖으로 잘리거나 테두리를 넘지 않는지 확인합니다.

## Step 4 완료 후: 보스 패턴, 4룬 퍼즐 UI, 아카이브 제출

1. 보스 장판 예고(`circle`, `cross`, `ring`), 충격파(`waves`), 봉인의 제단 4룬 단서 문구와 점등 진행도가 화면에 표시되는지 확인합니다.
2. 제출 전 보안 금지 패턴(`eval`, 인라인 `on*=`, 외부 데이터 `innerHTML`, 외부 도메인 URL)이 없는지, 번들러 출력이 상대 경로(`./`)인지 점검합니다.
3. 신규 토큰 기준(`me.classChosen === false`) 초기 화면에서 불투명 모달이 던전 전체를 가리지 않는지 확인하거나 `--thumbnail` 이미지를 준비합니다.
4. `node .agents/skills/submit-client/scripts/submit-client.mjs`를 실행해 보안 검사와 `800x500` 썸네일 캡처를 통과하고, 출력된 제출자 `codename`이 브라우저 플레이어 이름과 일치하는지 확인합니다.
